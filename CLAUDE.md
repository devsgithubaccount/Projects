## Development Workflow

### Branching

- Feature branches should be created off the default branch.
- Use descriptive branch names that reflect the work being done.

### Commits

- Write clear, concise commit messages that explain *why* a change was made.
- Keep commits focused — one logical change per commit.

### Code Quality

- Review all changes before committing.
- Do not commit secrets, credentials, or environment-specific configuration files (e.g., `.env`).

## Conventions

- Prefer simple, readable code over clever abstractions.
- Only add complexity when justified by current requirements, not hypothetical future ones.
- Keep dependencies minimal and well-justified.
